# Сокеты

ZeroMQ - библиотека сокетов, которые обмениваются сообщениями напрямую: без сервера и без
хранения, а кто получит каждое сообщение, решает паттерн.

<Diagram name="sockets" words={words} />

Каждый блок на схеме - сокет в каком-то процессе. Сообщение идёт от одного сокета к другому по
соединению между ними. После этого его никто не хранит, поэтому сокет, который в этот момент не
подключён, его не увидит.

Какая сторона слушает, а какая подключается, не зависит от того, в какую сторону идут сообщения.
Устойчивая часть топологии привязывается к адресу, а части, которые появляются и исчезают,
подключаются к ней. В конвейере вентилятор и приёмник привязываются, а воркеры подключаются к
обоим. [`ZmqEndpoint`](../../components/broker/endpoint/index.md) задаёт сторону, которую
занимает этот сервис.

Сокет PUSH раздаёт сообщения подключённым узлам по очереди: одно сообщение одному узлу. Сокет PULL
читает от всех своих узлов по очереди, поэтому ни один узел не оттесняет остальные. Это
[`ZmqQueue`](../../components/broker/zmq-queue.md).

Сокет SUB отправляет свои фильтры тому PUB, к которому подключён. PUB сравнивает первый кадр
каждого сообщения с каждым фильтром по префиксу и отправляет сообщение только туда, где фильтр
совпал. Сообщение, которому не подошёл ни один фильтр, отбрасывается, и издатель об этом не
узнаёт. Это [`ZmqFanout`](../../components/broker/zmq-fanout.md), где имя подписки служит её
[фильтром](../../components/subscriptions/prefixes.md).

Сокет ROUTER даёт каждому соединению идентичность. Он ставит идентичность перед каждым полученным
сообщением и отправляет сообщение тому соединению, идентичность которого стоит в первом кадре.
DEALER отправляет и принимает сообщения без кадра идентичности. Это
[`ZmqRpc`](../../components/broker/zmq-rpc.md), а страница [Кадры](frames.md) показывает конверт.

У сокета может быть много узлов, а порядок сохраняется только между двумя сокетами одной пары.
`ruststream-zeromq` работает на `tcp://` и `ipc://`. Другую схему адреса брокер отвергает при
подключении, до того как откроется хоть один сокет.

Это паттерны самого ZeroMQ ([конвейер](https://rfc.zeromq.org/spec/30/),
[публикация-подписка](https://rfc.zeromq.org/spec/29/),
[запрос-ответ](https://rfc.zeromq.org/spec/28/)), а
[zguide](https://zguide.zeromq.org/docs/chapter2/) объясняет, какая сторона привязывается.
