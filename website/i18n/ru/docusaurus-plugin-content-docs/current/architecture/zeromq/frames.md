# Кадры

Соединение ZMTP открывается приветствием и командой READY, затем передаёт сообщения из кадров;
сообщение этого крейта - три кадра: имя, заголовки, полезная нагрузка.

<Diagram name="frames" words={words} />

ZMTP - протокол, на котором работает каждый сокет ZeroMQ. Оба узла отправляют приветствие с
версией протокола и механизмом безопасности. Клиент `zeromq` указывает в приветствии версию 3.0 и
механизм NULL, который не проверяет подлинность и не шифрует. Затем каждый узел отправляет команду
READY со своим типом сокета, и если типы несовместимы, соединение на этом закрывается.

Сообщение - это список кадров. Каждый кадр, кроме последнего, помечен флагом MORE, поэтому
получатель знает, где кончается одно сообщение. Сокет передаёт сообщение целиком или не передаёт
ничего.

Этот крейт кладёт в каждое сообщение три кадра. Кадр 0 - имя, кадр 1 -
[заголовки](../../components/wire/headers.md), кадр 2 - полезная нагрузка. Узел на любом языке
составляет такое сообщение одной многочастной отправкой, как показывает
[формат передачи](../../components/wire/index.md). Сообщение из двух кадров читается как имя и
полезная нагрузка без заголовков.

Кадр полезной нагрузки - это сам буфер, который записал кодек, а не его копия. Каждый издатель
этого крейта забирает байты, которые закодировал рантайм, а кадр владеет своими байтами, поэтому
буфер и становится кадром.

## Запросы и ответы {/* #requests-and-replies */}

<Diagram name="envelope" words={envelope} />

ROUTER отвечающей стороны читает запрос, перед тремя кадрами которого стоит идентичность
запрашивающей стороны. Крейт превращает эту идентичность в заголовок `reply-to`: префикс
`zmq-reply:` и за ним идентичность в шестнадцатеричном виде. Ответ обработчика адресуется туда.
[Отвечающая сторона](../../components/request-reply/responders.md) монтирует преобразование,
которое задаёт этот адрес для каждой доставки.

На обратном пути кадры такие: идентичность, буквальное имя `reply`, заголовки и полезная нагрузка.
ROUTER отправляет их соединению, которое названо идентичностью, и снимает идентичность.

Запрос уходит через собственный DEALER со своей случайной идентичностью, поэтому ответ может дойти
только до того запроса, который его задал. В запросе есть заголовок `correlation-id`; если
вызывающий код задал его сам, значение сохраняется. Ответ с тем же идентификатором завершает
запрос. Заголовки перечислены на странице [Конверт](../../components/wire/envelope.md).

Протокол - [ZMTP 3.0](https://rfc.zeromq.org/spec/23/), а конверт с идентичностью взят из
[паттерна запрос-ответ](https://rfc.zeromq.org/spec/28/).
