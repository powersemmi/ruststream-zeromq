# Конвейеры на PUSH/PULL

Это руководство строит конвейер из [руководства ZeroMQ](https://zguide.zeromq.org/docs/chapter1/#Divide-and-Conquer): вентилятор отправляет задания, воркеры конкурируют за них, а приёмник собирает результаты.

В примере два сервиса.
Воркер берёт задания у вентилятора и по каждому отправляет результат приёмнику.
Приёмник собирает результаты пакетами.
Вентилятор - любой узел, который отправляет задания, например узел на Python из руководства [Начало работы](getting-started.md).

## Кто привязывается к адресу

Устойчивая сторона соединения привязывается к адресу, а сторона, которая появляется и исчезает, подключается.
В конвейере устойчивы вентилятор и приёмник, поэтому привязываются они.
Воркеры подключаются к обоим, и каждый новый процесс воркера - ещё одно подключение.

Сторону задают [`ZmqEndpoint::bind`](../components/broker/endpoint/bind.md) и [`ZmqEndpoint::connect`](../components/broker/endpoint/connect.md).
Сторона входит в тип брокера: брокер на `connect` - это `ZmqQueue<Connect>`.
От неё зависит, что брокер может публиковать и куда может уйти копия для повтора, поэтому ошибка обнаруживается во время компиляции или при старте, а не в работе.

Брокер `ventilator` подключается к вентилятору, и его подписка читает задания.
Воркеры, подключённые к одному вентилятору, конкурируют: PUSH отдаёт каждое задание одному воркеру по очереди.

Результаты уходят через второй брокер, `sink`, который подключается к приёмнику.
[`bindable()`](../components/publishing/index.md) превращает брокер в такой, к которому можно привязать политики публикации, а `sink.bind(Publish)` - политика, которая публикует через него.
`.out_reply(results)` отправляет туда каждый `Done`.
Ответить через брокер `ventilator` воркер не может: вентилятор только отправляет, поэтому после подключения подписки брокер отвергает любую публикацию.
Эти отказы описывает страница [Ответы](../components/publishing/replies.md).

Подписка, которая подключается, тоже называет, куда уходят её [копии для повтора](../components/settlement/out-retry.md), даже если её обработчик никогда не просит повтора.
Здесь они уходят в `retries` - очередь, которую воркер привязывает для себя, и её читает тот же обработчик.
У копии имя `jobs` - имя подписки, которая принимает её обратно.
Повторы целиком разбирает руководство [Повторы и очереди dead-letter](retries.md).

Приёмник привязывается к адресу, к которому подключаются воркеры.
Привязанный сокет PULL принимает всё, что ему отправляет любой воркер, поэтому одна подписка читает результаты всех воркеров.
`collect` принимает срез, поэтому получает [пакеты](../components/subscriptions/batches.md).
Пакет закрывается, когда в нём набралось 32 результата или прошло 20 мс после первого результата, смотря что наступит раньше.
Кадры при передаче не меняются: пакет собирается на стороне приёмника.

## Один вид работы на конечную точку

PUSH и PULL не смотрят на кадр имени.
Привязанная очередь передаёт своей подписке каждое отправленное ей сообщение, какое бы имя в нём ни стояло.
Поэтому второму виду работы, например отчётам рядом с заданиями, нужны своя конечная точка и свой брокер.
Вторую подписку на привязанной конечной точке старт отвергает, и ошибка называет обе подписки.

## Порядок и ключи

PUSH раздаёт сообщения подключённым воркерам по очереди и ключ не читает.
Два задания одного клиента могут выполняться на двух воркерах одновременно.
Обработчик, которому нужно видеть задания одного клиента по порядку, работает в одном процессе воркера.
Внутри одного процесса [`workers`](api:ruststream::runtime::Workers) в точке монтирования выполняет несколько доставок обработчика одновременно.
У сообщения ZeroMQ нет ключа, поэтому пути обработки, разбитые по ключу через `by_key`, получают его доставки по очереди.

## Проверка конвейера

В каждом файле примера есть тест, который запускает свой сервис через `TestApp::start`.
Тест воркера отправляет задание так, как это сделал бы вентилятор, и читает результат, опубликованный в `results` на брокере `sink`.
Тест приёмника отправляет сразу три результата и проверяет, что `collect` получил их одним пакетом.
Обвязку разбирает руководство [Тестирование сервиса на ZeroMQ](testing.md).
