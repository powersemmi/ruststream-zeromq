    快速开始

    本指南安装 ruststream-zeromq，运行第一个工作者，并从另一个进程中的对端向它发送任务。

    安装​

    Cargo.toml
    [dependencies]
    ruststream = { version = "0.7", features = ["macros", "json", "logging"] }
    ruststream-zeromq = "0.7"
    serde = { version = "1", features = ["derive"] }
    tracing = "0.1"

    [dev-dependencies]
    ruststream-zeromq = { version = "0.7", features = ["testing"] }
    tokio = { version = "1", features = ["macros", "rt"] }

    ruststream 是框架本身：macros 提供属性宏，json 提供默认编解码器，logging 把服务的日志打印到终端。 ruststream-zeromq 是 ZeroMQ Broker。 它的 testing feature 加入测试所用的进程内模式。

    这个 Broker crate 有以下 feature：

    Feature提供的内容
    asyncapi生成的 AsyncAPI 文档中的 x-ruststream-zeromq 扩展
    testingTestApp 背后的进程内模式

    ZeroMQ 没有服务器，因此不需要安装或启动任何东西。 本 crate 通过 zeromq 使用 ZMTP 协议通信，这是一个用 Rust 编写的客户端。 因此构建既不需要 libzmq，也不需要 C 编译器。 两个进程直接通信，经由 tcp://，或者经由 ipc://，即同一主机上的 Unix 套接字。

    第一个服务​

    • 宏
    • 手写
    src/main.rs
    use ruststream_zeromq::queue::prelude::*;
    use serde::Deserialize;

    #[derive(Debug, PartialEq, Deserialize)]
    struct Job {
        id: u64,
        items: u32,
    }

    #[subscriber("jobs")]
    async fn take_job(job: &Job) -> HandlerOutcome {
        if job.items == 0 {
            tracing::warn!(job.id, "job without items dropped");
            return HandlerOutcome::drop();
        }
        tracing::info!(job.id, job.items, "job taken");
        HandlerOutcome::ack()
    }

    #[ruststream::app]
    fn app() -> impl App {
        RustStream::new(AppInfo::new("worker", "0.1.0")).with_broker(
            ZmqQueue::new(ZmqEndpoint::bind("tcp://127.0.0.1:5555")),
            |b| {
                b.include(take_job);
            },
        )
    }
    src/main.rs
    use ruststream_zeromq::queue::prelude::*;
    use serde::Deserialize;

    #[derive(Debug, PartialEq, Deserialize, JsonSchema)]
    #[schemars(crate = "ruststream::schemars")]
    struct Job {
        id: u64,
        items: u32,
    }

    struct TakeJob;

    impl Handle<Job> for TakeJob {
        fn handle(
            &self,
            job: &Job,
            _outs: &(),
            _ctx: &mut Context<'_>,
        ) -> impl Future<Output = Result<(), HandlerOutcome>> {
            if job.items == 0 {
                tracing::warn!(job.id, "job without items dropped");
                return ready(Err(HandlerOutcome::drop()));
            }
            tracing::info!(job.id, job.items, "job taken");
            ready(Ok(()))
        }
    }

    fn app() -> impl App {
        RustStream::new(AppInfo::new("worker", "0.1.0")).with_broker(
            ZmqQueue::new(ZmqEndpoint::bind("tcp://127.0.0.1:5555")),
            |b| {
                b.include(subscriber("jobs", TakeJob).build());
            },
        )
    }

    fn main() -> ExitCode {
        run_main(app)
    }

    take_job 从 jobs 读取 JSON 任务。 它确认带有条目的任务，丢弃没有条目的任务。 ZmqQueue 是 PUSH/PULL 模式：每个任务只到达一个工作者。 ZmqEndpoint::bind 表示本进程在这个地址上监听。 ZmqQueue::new 只记录端点；套接字在服务启动时才打开。 #[ruststream::app] 把 app 变成 main；在手写形式中，run_main 做同样的事。

    运行服务：

    cargo run -- run

    对端​

    任何使用 ZMTP 协议的进程都可以向工作者推送任务。 一条消息由三帧组成：名称、消息头和载荷（线上格式）。 下面这个 Python 对端使用 pyzmq：

    push_job.py
    import json
    import zmq

    push = zmq.Context().socket(zmq.PUSH)
    push.connect("tcp://127.0.0.1:5555")
    push.send_multipart([b"jobs", b"", json.dumps({"id": 1, "items": 3}).encode()])
    push.close(linger=1000)

    在另一个终端里运行它：

    python3 push_job.py

    服务记录一条 job taken 日志，其中带有任务的 id 和条目数。 紧接着是一条警告 ack / nack failed：这个 Broker 不支持确认。 ZeroMQ 在线路上没有确认，因此工作者读到任务时，任务就算完成（确认）。 Ctrl+C 停止服务。 对端也可以是一个 RustStream 服务：基于 PUSH/PULL 的流水线构建了一个把结果推送给另一个服务的服务。

    从 pyzmq 或 libzmq 迁移​

    基于 ZeroMQ 语言绑定的服务要自己打开套接字，自己编写接收循环。 下表列出每一部分在 RustStream 中的位置：

    pyzmq 或 libzmqRustStream
    ctx.socket(zmq.PULL) 和 bindZmqQueue::new(ZmqEndpoint::bind(..)) 加一个 #[subscriber] 处理器
    connectZmqEndpoint::connect；连接的哪一端是 Broker 类型的一部分
    recv_multipart 循环处理器，每条消息调用一次
    解码载荷帧处理器的参数类型，由编解码器解码
    send_multipart回复或 Out 参数，经由发布策略发送
    setsockopt(zmq.SUBSCRIBE, prefix)ZmqFanout 上的订阅名称（基于 PUB/SUB 的广播）
    REQ 和 REP基于 DEALER 和 ROUTER 的 ZmqRpc（请求与回复）
    tcp://*:5555tcp://0.0.0.0:5555
    inproc://测试用 TestApp；同一主机上的进程之间用 ipc://
    SNDHWM 和 RCVHWMread_ahead（在生产环境中运行）
    监视多个套接字的 zmq.Poller每个套接字一个订阅，各自运行在自己的任务上
