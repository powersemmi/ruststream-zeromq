    Frames

    A ZMTP connection opens with a greeting and a READY command, then carries messages of frames; this crate's message is three frames: name, headers, payload.

    ZMTP is the protocol under every ZeroMQ socket. Both peers send a greeting with the protocol version and the security mechanism. The zeromq client greets with version 3.0 and the NULL mechanism, which neither authenticates nor encrypts. Then each peer sends a READY command with its socket type, and a pair of types that do not belong together ends the connection there.

    A message is a list of frames. Every frame but the last carries the MORE flag, so the receiver knows where one message ends. A socket hands over a whole message or nothing.

    This crate puts three frames in every message. Frame 0 is the name, frame 1 the headers, frame 2 the payload. A peer in any language composes one with a single multipart send, as the wire format shows. A message of two frames is read as a name and a payload with no headers. A message of one frame, what a plain ZeroMQ peer sends, is read as the payload with an empty name, and a SUB matches its prefix against that frame. A message of more frames is refused as a wire error.

    The payload frame is the buffer the codec wrote, not a copy of it. Each publisher of this crate takes the bytes the runtime encoded, and a frame owns its bytes, so the buffer becomes the frame.

    Requests and replies​

    The responder's ROUTER reads a request with the requester's identity in front of the three frames. The crate turns that identity into the reply-to header, zmq-reply: followed by the identity in hexadecimal, and the handler's reply is addressed there. A responder mounts a transform that names that destination per delivery.

    On the way back the frames are the identity, the literal name reply, the headers and the payload. The ROUTER sends them to the connection the identity names and takes the identity off.

    A request goes out on a DEALER of its own, with a random identity of its own, so an answer can reach only the request that asked. The request carries a correlation-id header, kept when the caller set one, and the reply that carries the same id resolves it. The identity frame page lists the headers.

    The protocol is ZMTP 3.0, and the identity envelope is the request-reply pattern's.
